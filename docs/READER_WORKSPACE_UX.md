# FastMarkdownViewer 阅读界面改版

## 产品目标

主要场景是从资源管理器打开 Markdown、在几十份已打开的文件间切换，以及专注阅读长文档。目标是在同一窗口完成这些动作，并区分“按文件名找文件”和“在正文里查找”。

## 界面与优先级

| 优先级 | 用户动作 | 界面决策 |
| --- | --- | --- |
| P0 | 打开或拖入文档 | 顶部提供常驻“打开”按钮。空状态保留明确的拖入提示和打开按钮，常用快捷键集中展示。 |
| P0 | 从很多已打开文件中找一份 | 左栏在文件列表上方放置筛选框，显示匹配数。支持文件名和完整路径的部分匹配，悬停可区分同名文件。 |
| P0 | 用键盘直接切换文件 | Ctrl+P 打开并聚焦筛选框。输入后按 Enter 打开首个匹配结果，Esc 清除筛选并回到阅读。macOS 使用 Command+P。 |
| P0 | 读长文档或在窄窗口阅读 | 视图菜单提供专注阅读，F9 切换。暂时收起顶部标签、文件列表和目录，保留顶部入口和正文查找。退出时恢复原布局。 |
| P1 | 查看整个目录中的文档 | 单独评估文件夹导航，包括目录范围、子目录和同名文件处理。 |

正文继续使用现有的只读渲染、主题和阅读位置机制。筛选与专注模式属于当前窗口的临时状态。现有主题及视图偏好继续随会话保存。

## 验收场景

1. 新窗口和阅读中的窗口都可直接打开文件。已有的文件菜单、拖入和 Ctrl+O 也可使用。
2. 打开 40 份文档后，Ctrl+P 可以从隐藏侧栏的状态进入筛选，选择文件后打开对应正文。无匹配时保持当前文档并给出反馈。
3. 专注模式隐藏导航，退出后恢复原先的标签栏和侧栏状态。正文查找和文档切换仍可使用。
4. 验证中文和英文菜单、窄窗口、已有会话恢复，以及主题、目录、标签拖拽和正文渲染的回归。

流程依据 [BMad Build a Change](https://docs.bmad-method.org/build/build-a-change/)，在现有桌面应用中按需求、体验决策、实现和验收推进。
